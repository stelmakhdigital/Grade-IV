# AGENTS.md — проект «Грейд» (сервис мок-интервью, dir: INTERVIEW)

> Файл читается ИИ-агентом при начале работы над проектом.
> Содержит правила работы, указатели на контекст и договорённости.

## 1. Проект в одном абзаце
Онлайн-сервис **мок-интервью для разработчиков** (рабочее название «Грейд», см. существующий лендинг).
Ядро — AI-сервис, который проводит мок-интервью:
- **Голосовое интервью** — кандидат общается голосом с ИИ-интервьюером в формате «zoom-call»: ИИ говорит (TTS) и слушает кандидата (STT/ASR).
- **Стадия Live-Code** (живой кодинг) — онлайн-редактор кода: кандидат решает задачу вживую, код выполняется (тесты), ИИ-интервьюер/ревьюер разбирает решение и задаёт follow-up вопросы.
- **Стадия System Design** (Middle/Senior) — whiteboard для проектирования систем: палитра готовых архитектурных блоков + свободное рисование; ИИ оценивает схему и устный ответ.

## 3. Обязательные правила ИИ-агента
1. Перед каждым шагом ИИ-агент составляет todos / чеклист / план реализации шага на русском языке и кратко рассказывает его пользователю.
2. В todos ИИ-агент должен записать следующие пункты: **Компиляция и тестирование**, **Получить разрешение от пользователя на коммит**.
3. Каждое свое размышление сопровождает кратким саммари на русском языке для пользователя.
4. Каждое свое действие сопровождает кратким описанием на русском языке для пользователя.
5. Выполняет шаг этапа и по ходу реализации обновляет todo если надо и после каждого пункта отмечает выполненный пункт в todo и пишет промежуточный результат пользователю, чтобы пользователь понимал что происходит.
6. После каждого шага ИИ-агент сообщает пользователю какая была цель, что сделал ИИ-агент для ее реализации и как он понял что все сделано, **в этот момент нельзя коммитить**.
7. Если пользователь одобряет (явно говорит коммитить), то прежде чем перейти к следующему шагу реализации ИИ-агент должен закоммитить изменения и отметить пункты выполненных работ в файле `roadmap.md`.

## 4. SDLC и методология
- Проект ведётся по фазам SDLC (см. `roadmap.md`): Discovery → Requirements → Design → Implementation → Testing → Deployment → Operations.
- Учитывается методология **PMBOK** («РМВОК» в формулировке пользователя): фазовые входы/выходы (phase gates), WBS, управление рисками и изменениями, коммуникации.
- Каждая фаза имеет критерии выхода и явное одобрение пользователя.

## 5. Технические допущения (подтверждено на Discovery, 2026-09-09)
- Язык: только русский (интервью и голос ИИ).
- Голосовой контур: микрофон (Web Audio) → streaming STT → LLM (интервьюер) → streaming TTS;
  естественный живой диалог: интонации, паузы, ИИ сам заполняет долгие паузы кандидата.
  Self-hosted стек: STT — faster-whisper large-v3-russian (GPU), TTS — Silero v5 (MIT);
  сервисные эндпоинты /api/v1/stt, /api/v1/tts + абстракция провайдера (подменяемо).
- LLM-интервьюер: Qwen3.8-27B (self-hosted, Apache 2.0 — коммерческое использование OK;
  модель с vision — может оценивать схемы whiteboard по изображению).
- Язык бекэнда: **Go** (api, sandbox — ADR-006); voice-сервис — Python (ML: faster-whisper,
  Silero v5, torch) за `/api/v1/stt|tts` + `VOICE_URL`.
- Live-Code: редактор Monaco + сандбокс выполнения кода/тестов (Docker) + ИИ-ревьюер.
- System Design: whiteboard (палитра архитектурных блоков + свободное рисование), ИИ-оценка схемы + устного ответа.
- MVP: все стадии (голос, Live-Code, System Design, отчёт) для Go + Python; поминутная тарификация,
  лимит 60 минут бесплатно, платёжный шлюз не нужен.
- Платформа: Web (браузер) — подтверждено (2026-09-09).

## 6. Политика коммитов
- Коммит — только при явном разрешении пользователя.
- Тесты/проверки (пункт 2 правила 3) выполняются до запроса разрешения.
- После коммита — обновить статусы в `roadmap.md` и лог в `PROJECT_MEMORY.md`.
