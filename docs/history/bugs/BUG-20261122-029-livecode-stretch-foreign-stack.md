# BUG-20261122-029: stretch-пул Live-Code брался по sess.Stack — чужие стеки и файлы градатора кандидату

**Дата:** 2026-11-22
**Серьёзность:** P0 (утечка градатора, чужой язык практики)
**Статус:** closed (fix: ws.go)
**Отчёт:** https://github.com/stelmakhdigital/Grade-IV/issues/3

## Симптомы

В `enterLiveCode` основной пул брался по `s.liveCodeStack(sess)` (стек сессии →
иначе рантайм роли → иначе пусто), а stretch-пул следующего грейда — по
`string(sess.Stack)`. У legacy-сессий (все sysadmin-строки, созданные до spec-22,
лежат с `stack = ''`; тот же результат даёт роль, которой нет в файле ролей)
запрос в sandbox уходил без фильтра по стеку, `Bank.List` отдавал задачи всех
стеков, и кандидат shell-практики получал задачи go/python.

`sanitizeTasks` вызывался со стеком стадии (`shell`), а `isGraderFile` для `shell`
знал только `check.sh` — `solution_test.go` чужой задачи уходил клиенту в
stage-сообщении и в событии `livecode_tasks` (то есть в транскрипт и отчёт).
Повтор BUG-20261104-027. Запуск такой задачи всё равно падал: runner отклоняет
стек `''`, поэтому итог — вторая вкладка с чужим языком, открытые тесты и
неработающий «Запустить тесты».

## Причина

Два разных источника стека для одного набора задач + `sanitizeTasks`, который
при пустом/чужом стеке не вырезал ничего (`isGraderFile` по умолчанию `false`).

## Исправление

- `ws.go` `enterLiveCode`: один источник стека (`stageStack := s.liveCodeStack(sess)`)
  для обоих пулов; при пустом `stageStack` задачи не берутся вообще (запроса в
  банк без фильтра по стеку нет), кандидат получает «задачи ещё не назначены».
- `ws.go` `isGraderFile`/`sanitizeTasks`: параметр `stack` убран, маски рантаймов
  (`*_test.go`, `*_test.py`, `test_*.py`, `check.sh`) применяются все сразу —
  несовпадение стека стадии и стека задачи больше не открывает градатор.

## Проверка

- `TestEnterLiveCodeEmptySessionStack`: WS-проба на сессии с `stack = ''` и ролью
  sysadmin (middle) — все задачи shell, stretch = shell-s1, ни одного запроса
  к банку без стека, файлов градатора в выдаче нет.
- `TestEnterLiveCodeUnknownRole`: пустой стек + роль вне файла ролей — задач нет,
  запросов в банк нет.
- `TestSanitizeTasksGraderFiles`: из смешанного набора файлов остаются только
  кандидатские (`solution.*`, `access.log`).
- На старом коде обе WS-пробы падают (`[shell-m1 shell-m2 py-s1]`).
- `go test ./...` (api, sandbox), `go vet`, `gofmt` — чисто.
