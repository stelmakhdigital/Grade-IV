# BUG-20261122-033: файлы градатора лежали в workdir кода кандидата — сдача читала check.sh и получала pass

**Дата:** 2026-11-22
**Серьёзность:** P0 (утечка градатора + обход проверки на честность)
**Статус:** closed (fix: файлы банка пишутся в отдельный каталог, в docker — ro-mount /grade)
**Связано с:** BUG-20261104-027 (там закрыли только границу WS: `sanitizeTasks`
прячет файлы градатора из stage-сообщения; в песочнице они оставались в каталоге
решения). Issue #9.

## Симптомы
Sandbox писал доверенные файлы задачи (банк) в тот же каталог, где исполняется
код кандидата, и код кандидата имел к ним полный доступ. Одна сдача в задаче
`shell-sum-avg`:

```bash
#!/usr/bin/env bash
cat check.sh >&2          # stdout решения чек съедал в OUT=$(...)
grep -oE 'sum=[0-9]+|avg=[0-9]+' check.sh | sed 's/^/READ /' >&2
```

возвращала кандидату исходник градатора в `run_result.stdout` (stdout+stderr
прогона уходят кандидату целиком — `runs_handlers.go`) и все ожидаемые значения
ассертов (`sum=10`, `avg=2`, `sum=5`, `avg=5`). По тому же каталогу чек и
переписывался:

```bash
#!/usr/bin/env bash
echo 'exit 0' > check.sh   # workdir примонтирован :rw, файл 0644
```

— после этого проходило любое неверное решение (`passed: true`).

Аналогично для go (`init()` читает `solution_test.go`) и python
(`print(open("solution_test.py").read())` — модуль импортируется при сборе
pytest). Воспроизведено тестом на коде до правки (`Run(ctx, stack, files)`,
sha 205d5cf): регресс из `grader_isolation_test.go` в адаптированном виде падал
и на чтении («READ sum=10» в выводе), и на подмене (неверное решение прошло чек).

## Причина
`handleRun` смешивал файлы кандидата и файлы банка в один `files`
(`merged[name] = content`), а `Run` писал их в один `workdir` с правами 0644,
после чего команда прогона (`bash check.sh`, `pytest`, `go test`) запускалась в
этом каталоге. «Исполняются ТОЛЬКО файлы банка» было верно по составу
исполняемых файлов, но не по конфиденциальности: `isTaskTestFile` решал задачу
«троян вместо теста не исполнится», а не «градатор скрыт».

В docker-режиме каталог монтировался `-v workdir:/work:rw`, а `--user` — uid
процесса sandbox, так что права файлов кандидату не мешали ни читать, ни писать.

## Исправление
Граница — вход `Run` и раскладка каталога прогона:

- `Run(ctx, stack, files, trusted)` — файлы кандидата и файлы градатора теперь
  разные аргументы. `handleRun` (`cmd/sandbox/main.go`) берёт из банка только
  файлы градатора (`tasks.IsGraderFile` — общий предикат вместо локального
  `isTaskTestFile`) и подаёт их отдельно.
- Каталог прогона: `<workdir>/run` (решение, cwd прогона) и `<workdir>/grade`
  (градатор, 0444) — соседи, а не одно дерево. В docker `/grade` монтируется
  отдельно и только на чтение (`-v <gradedir>:/grade:ro`).
- Команды прогона берут градатор из плейсхолдера `%GRADER%`:
  shell — `bash %GRADER%/check.sh`, python — `pytest -p no:cacheprovider %GRADER%`
  (тесты собираются из каталога градатора, решение импортируется из cwd),
  go — `go test -overlay %GRADER%/overlay.json` (тесты банка подмешиваются в
  пакет оверлеем, на диске решения их нет).
- Подставной `check.sh` / `*_test.go` / `test_*.py` из файлов кандидата по-прежнему
  не исполняется: файл-двойник лежит в `/work`, градатор запускается из `/grade`,
  а go-тест подменяется оверлеем.

Что осталось (осознанно, не «починить» молча): код кандидата идёт под uid
процесса sandbox, поэтому чтение `/grade/check.sh` (docker) или
`../grade/check.sh` (subprocess) по абсолютному пути доступно. Права не спасают:
владелец тот же. Закрывается только раздельными uid процесса кандидата и
каталога градатора. Записи/подмены в docker нет — монтирование только для
чтения; в subprocess-режиме (dev-fallback) перенаправление не проходит
(файлы 0444), а rename/unlink формально возможны.

## Проверка
- `services/sandbox/internal/runner/grader_isolation_test.go` — регресс на оба
  шага атаки (чтение из cwd, подмена) для shell в обоих режимах, листинг cwd на
  отсутствие файлов банка (go/python/shell), игнорирование `check.sh` кандидата,
  честные решения проходят (go — оверлей + «троян» не исполняется, python —
  pytest из каталога градатора).
- `go vet ./... && go test ./... -count=1` в `services/sandbox` — зелено.
- Docker-режим: `SANDBOX_DOCKER=1 SANDBOX_IMAGE_PYTHON=grade/python-tests:dev
  go test ./...` — изоляция, shell/go/python-прогоны проходят; go-проба
  `TestSandboxDockerProbe` падает и до правки (28 ядер хоста: параллельная
  сборка stdlib не влезает в `--pids-limit=128` → `fork/exec … resource
  temporarily unavailable`), overlay-путь в docker проверен отдельной пробой с
  `GOFLAGS=-p=2`.
