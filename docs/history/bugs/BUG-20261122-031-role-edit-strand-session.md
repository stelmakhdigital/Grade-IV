# BUG-20261122-031: роль поправили во время сессии — стадия вне программы, все переходы закрыты

**Дата:** 2026-11-22
**Серьёзность:** P1 (кандидат застревает на Live-Code: отказ на любой `stage_action`,
собеседование заканчивается без стадии «доска»)
**Статус:** closed (fix: программа стадий закрепляется за сессией)
**Отчёт:** https://github.com/stelmakhdigital/Grade-IV/issues/7

## Симптомы

Роль `dev` с `practice: {runtime: "go"}`, сессия middle дошла до Live-Code.
Админ снимает «Практика в редакторе» и сохраняет роль. Рестарт API (деплой,
рестарт контейнера) — рантаймов в памяти нет, кандидат переподключается по WS.
После этого любой `stage_action` даёт отказ:

- `design`, `voice` — «стадия не входит в программу грейда»;
- `report` — «недопустимый переход между стадиями: livecode → report».

UI остаётся на Live-Code, работает только «Завершить» (`engine.Finish` программу
стадий не проверяет). Тот же результат без участия админа: деплой с другим
`ROLE_TRACKS_FILE`.

## Причина

Реконструкция рантайма (issue #1, `c4d9d53`) резолвит роль по **текущему**
файлу ролей (`resolveTrack` в `Attach` и `reconstructFromStore`). Программа
стадий берётся из `Track.Stages(grade)`, то есть из живой роли: сняли практику —
`livecode` из программы выпадает, и `CanTransitionStage` не находит текущую
стадию кандидата в программе. До `c4d9d53` после рестарта роль была `nil` и
программа считалась по легаси-правилу грейда, так что этот путь работал: фикс #1
закрыл потерю роли и открыл безвыходное состояние.

Программа роли нигде не закреплялась за сессией: в `sessions` были `track_id` и
`stack` (рантайм практики), но не состав стадий. Колонка `program` для этого не
пригодна — в ней текст программы голосовой стадии из шаблона (уходит в
system-промпт, `interviewer.go`).

## Исправление

- `sessions.stages` (миграции в `db/db.go`, `db/sessionstore.go`): программа
  стадий фиксируется при `create` (`session/engine_lifecycle.go`) и читается при
  реконструкции (`Attach`, `reconstructFromStore`). `CanTransitionStage` и
  `CanJumpStageDebug` теперь принимают саму программу, а не роль: движок валидирует
  переход по программе сессии, живая роль остаётся для меты стадии и доски.
  У строк до колонки (`stages = ''`) программа считается по текущей роли, как раньше.
- `models.Track.StageMetaFor`: `stages` и `practice` в stage-сообщении берутся из
  программы сессии (`session/engine.go`, `httpapi/ws.go`). Иначе правка роли прячет
  в UI кнопку перехода, которую движок этой сессии разрешает.
- `CanTransitionStage`: выпуск в `report` с стадии, которой в программе нет —
  страховка для легаси-строк, чтобы состояние не было безвыходным.
- `PUT /api/v1/admin/tracks/{id}`: правка `practice` (наличие или `runtime`) роли с
  незавершёнными сессиями отвечает 409 (`CountActiveByTrack`, защита сопоставима с
  `DELETE`, `DELETE` не тронут). В `GET /admin/tracks` добавлено `active_sessions`,
  редактор роли (`AdminView.tsx`) по нему блокирует чекбокс «Практика в редакторе»
  и выбор рантайма; 409 показывает причину. Заодно починен `adminUpdateTrack`
  (`src/api.ts`): он слал POST вместо `PUT`, поэтому правка существующей роли из
  UI не доходила до обработчика.

Смена `practice.runtime` (`go` на `shell`) при идущих сессиях больше не меняет
стадию задним числом: и переходы, и банк задач, и прогон (`liveCodeStack`) идут по
закреплённым за сессией `stages` и `stack`.

## Проверка

- `TestStageProgramFrozenAtCreate` (`session`): сессия с практикой доходит до
  Live-Code, роль правится на «без практики», рестарт движка поверх той же БД +
  `Attach` — `livecode → design → report` проходят, сессия завершена. Новая сессия
  на той же роли livecode не получает. На старом коде — падение на первом переходе
  («стадия не входит в программу грейда: design»).
- `TestCanTransitionStageOutsideProgram` (`session`): с выпавшей стадии есть
  выпуск в report, `voice`/`design` остаются закрыты.
- `TestAdminTrackPracticeGuard` (`httpapi`): снятие практики и смена рантайма у
  роли с активной сессией — 409, правка `title` — 200.
- `AdminView.test.tsx`: чекбокс и рантайм заблокированы у роли с
  `active_sessions > 0`, разблокированы у свободной; 409 на сохранение показывает
  причину.
- `go vet ./...`, `go test ./...` (api) — чисто; `npx tsc --noEmit`, `npx vitest run`
  (frontend) — 19 файлов / 142 passed. Postgres-ветка миграции не проверялась
  (прогон только на sqlite).
