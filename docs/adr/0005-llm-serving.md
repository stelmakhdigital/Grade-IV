# ADR-005. Сервинг LLM: vLLM + Qwen3.8-27B (prod) / llama.cpp + Qwen3-4B (локально)

**Статус:** принято (2026-09-09)

## Контекст
LLM-интервьюер — Qwen3.8-27B (решение #12): Apache 2.0, dense 27B, контекст 262K, native vision
(используется в ADR-004). Ограничения dev-машины: M2, 16 ГБ RAM, ~11 ГБ свободных на диске — 27B не помещается
(fp16 ≈ 55 ГБ, даже Q4 ≈ 16 ГБ). **Рантайм-цель prod — отдельный сервер в локальной сети
(AI-узел с GPU)** — vLLM; dev-машина используется только для разработки (решение #20).
Облачные API исключены (решение #16).

## Решение
Единый интерфейс — **OpenAI-совместимый chat completions (streaming)**; конфигурация:
`LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`.
- **Prod**: `vLLM` (OpenAI-compatible server) + Qwen3.8-27B, fp8/int8, GPU 80 ГБ
  (A100/H100/L40S) — docker-compose profile `gpu`. Ёмкость: 2–4 параллельные сессии
  (KV-cache + batching); оркестратор ведёт очередь.
- **Локальная dev**: `llama.cpp` server (OpenAI-совместимый, Metal) + **Qwen3-4B Q4_K_M
  GGUF** (~2.5 ГБ; 8B — опционально при свободном RAM). Качество ниже — задокументировано
  как dev-допуск; интерфейс и промпты те же.
- **MockLLM** (CI/тесты): детерминированный скриптованный провайдер — unit/integration-тесты
  без модели.

## Альтернативы
- **Qwen3.8-2.4T (Max)**: кастомная лицензия с условиями по выручке — отклонено (решение #13:
  только чистые коммерческие лицензии).
- **Облачные LLM-API**: отклонено (self-host only, решение #16).
- **Ollama**: проще локально, но слабее сервинг/батчинг 27B, чем vLLM; для локальной части
  llama.cpp — прямее (Metal, OpenAI-совместимый сервер).
- **Qwen3.8-27B на dev-машине**: не помещается (RAM/диск) — исключено расчётом.

## Последствия
- + Модель меняется конфигом (BASE_URL/MODEL) — backend независим от вендора сервинга.
- + Vision одной модели закрывает оценку схем (ADR-004) без отдельного сервиса.
- − Prod требует GPU-узел — AI-узел (отдельный сервер в ЛВС, compose profile `gpu`,
  требования к VRAM задокументированы).
- − Режим llama.cpp/4B — только convenience для разработки на dev-машине; prod-качество
  — Qwen3.8-27B на AI-узле (решение #20).
- − 262K контекст не нужен (сессия ≤ ~40K токенов) — `max-model-len` у vLLM ≈ 32K, экономия KV.
