# ADR-007. Стриминговый STT: WS /stt/stream, Silero VAD (onnx) на стороне voice, partial в UI

**Статус:** принято (2026-10-05)

## Контекст
Точка роста задержки и обрыв хвоста реплики (R5/R7): в ADR-002 граница реплики и
распознавание — batch-путь (локальный энергетический VAD в Go + `POST /stt` на
завершённой реплике): latency до транскрипта 3-с реплики ≈ 2,0 с (замер baseline),
а хвост реплики терялся, когда локальный VAD закрывал реплику раньше, чем
кандидат закончил говорить (пауза внутри фразы ≥ 900 мс).

## Решение
1. **Граница реплики — Silero VAD (onnx) на стороне voice-сервиса.** Новый
   WebSocket `/api/v1/stt/stream` (рядом с `/api/v1/stt`): клиент шлёт бинарные
   кадры PCM16 16 кГц mono (~250 мс); сервер — JSON:
   - `{"type":"state","speech":true|false}` — границы речи (Silero VAD);
   - `{"type":"partial","text":...}` — по мере распознавания, не чаще 1 раза / 500 мс
     (`PARTIAL_INTERVAL_S = 0.5`);
   - `{"type":"final","text":...,"confidence":...,"speech_ms":...}` — по завершённой
     реплике; `speech_ms` — длительность речи по VAD (используется Go для barge-in).
   Инкрементальная VAD-машина на окнах 512 сэмплов (32 мс); именованные константы
   (`services/voice/app/stt_stream.py`): `VAD_THRESHOLD = 0.5`,
   `VAD_MIN_SILENCE_MS = 600` (тишина ~600 мс после речи → final, вместо 900 мс
   batch-пути), `VAD_MIN_SPEECH_MS = 250` (короче — всплеск, без final),
   `PREROLL = 100 мс`.
2. **Silero — первичный провайдер VAD, энергетический — fallback.** onnx-модель
   Silero bundled в faster-whisper (`faster_whisper/assets/silero_vad_v6.onnx`,
   venv: `services/voice/.venv/lib/python3.14/site-packages/faster_whisper/assets/silero_vad_v6.onnx`).
   При недоступности onnx (`build_vad()` → `EnergyVAD`, log Warn) стрим работает в
   энергетическом режиме. `/api/v1/health` отражает VAD: поле `"vad": "silero"|"energy"`.
3. **Хвост не теряется (R5/R7):** final распознаётся на ВЕСЬ буфер реплики
   (pre-roll 100 мс → конец VAD + кадр с концом); partial — на буфер «на текущий
   момент». Распознавание — `faster-whisper large-v3` (GPU), то же качество, что
   в batch-пути, но результат приходит, пока VAD-хвост ещё доигрывается.
4. **API (Go):** WS-клиент `voicesvc.STTStream` (реконнект ≤3, пауза 500 мс).
   `feedVAD` по умолчанию шлёт PCM-кадры в стрим; частичное распознавание
   перекрывает VAD-хвост — отдельная pre-STT-механика на Go-стороне при стриме
   не нужна (pre-STT сохранён на batch-пути). `stt_partial` → WS в UI
   (интерим-строка кандидата); `final` → ход кандидата.
5. **Barge-in сохранён и улучшен:** во время TTS стрим слушает кандидата.
   Прерывание срабатывает **во время речи** — `state speech=true` (Silero VAD)
   запускает таймер `BargeInMinSpeechMS` (500 мс); если тишевая граница
   (`state speech=false`) не пришла — ИИ прерывается (tts_stop, end-кадр,
   `grade_barge_ins_total`, log Info). `final` — ход кандидата; если
   `speech_ms ≥ BargeInMinSpeechMS` и barge-in ещё не сработал (короткая
   реплика, таймер не успел) — прерывание догоняется по final. Однократность —
   CAS `sttBarged` (reset в `beginTTS`). Поведение совпадает со старым
   энергетическим VAD-путём (прерывание на ≥ 500 мс непрерывной речи), но
   детект речи — Silero, не энергия.
6. **Deградация:** WS-стрим voice недоступен (ошибка/таймаут подключения) —
   конвейер деградирует на текущий путь (энергетический VAD в Go + pre-STT +
   batch `/stt`), log Warn однократно на сессию, метрика-счётчик
   `grade_stt_stream_fallbacks_total`.

## Latency-бюджет (prod, GPU)
| Этап | ADR-002 (batch) | ADR-007 (стрим) |
|---|---|---|
| Граница реплики (тишина) | 0,9 с (локальный VAD) | 0,6 с (Silero, voice) |
| STT | 1,0 с (после границы) | пересекается с речью (partial); final — по готовности буфера |
| **Итого до транскрипта (3-с реплика)** | ≈ 2,0 с (замер) | ≈ 1,2–1,5 с (ожидаемо; замер в отчёте) |

## Альтернативы
- **Оставить batch, сократить VAD-хвост до 600 мс**: обрыв хвоста (R5) не решается —
  пауза внутри фразы всё равно закроет реплику.
- **Токеновый streaming ASR (whisper-streaming / chunk-ASR)**: больше движка
  (оверлап, калибровка чанков);Silero-VAD + partial «на буфер» даёт тот же UX
  (partial в UI) с меньшим кодом. Апгрейд — при деградации качества partial.

## Последствия
- + Partial-текст в UI (интерим-строка, `stt_partial`) и готовый текст раньше
  VAD-хвоста; хвост реплики не теряется.
- + Граница реплики — нейросетевой VAD (Silero): устойчивее к шуму/паузам, чем
  энергетический.
- − voice-сервис держит per-connection VAD-состояние (WS) — горизонтальное
  масштабирование voice остаётся stateless-по-HTTP, но WS-соединения привязаны
  к инстансу (стек single-node — допустимо).
- − Ещё один WS-путь api↔voice: реконнект + деградация на batch (покрытие:
  `TestSTTStreamFallbackToBatch`).
