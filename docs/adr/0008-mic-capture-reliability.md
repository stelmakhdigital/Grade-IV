# ADR-008. Надёжность захвата микрофона в браузере

**Статус:** принято (2026-10-08)

## Контекст
Инцидент 2026-10-08 (связанный с ADR-007-стримом и багфиксами 2026-09-16 /
2026-10-05): AudioWorklet-захват микрофона **молчал** (чанки PCM не шли),
сработал автоматический переход на ScriptProcessor-fallback (3 с без чанков,
см. багфикс 2026-09-16), но и fallback шёл **нулями** (rms 2→0, паттерн
инцидента из решения #34). Корневая причина **не определена**: пользователь
заменил/починил микрофон и обновил вкладку — после этого захват заработал.
Диагностика к тому моменту существовала (детектор «молчащего» входа:
rms < `SILENCE_RMS` (0.005) непрерывно ≥ `SILENCE_MS` (5000 мс) → состояние
`muted` + предупреждение «Микрофон молчит: проверьте устройство, мьют и
разрешения браузера», страница `/audio-debug.html` с проверками RAW/AEC/
worklet/резервного пути), но **конкретных действий пользователю не
предлагалось** — он не знал, что открыть и что проверить.

Предыстория:
- 2026-09-16: worklet молчит (browser не расписывает `process()`) → авто-фолбэк
  на `ScriptProcessorNode` + «Тест AudioWorklet» в `audio-debug.html`.
- 2026-10-05 (решение #34): `muted`-детектор в `src/audio/mic.ts`
  (`SilenceDetector`, `SILENCE_RMS`/`SILENCE_MS`), переход на fallback —
  info-сообщение через `onInfo` (не ошибка).

## Решение
1. **Цепочка надёжности захвата (поведение):**
   AudioWorklet → (нет чанков ≈ 3 с) → ScriptProcessor-fallback →
   (и там нет чанков) → **полная повторная инициализация** (заново
   `getUserMedia` + AudioContext + работающий путь). Повторные инициализации
   ограничены **именованной константой** (порядка 2 попыток); исчерпание
   лимита — ошибка в UI с указанием открыть диагностику `/audio-debug.html`.
   **Первый чанок с любого пути сбрасывает счётчик попыток** — после успешного
   начала потока счётчик не накапливается; пересоздания идут только пока чанки
   реально не приходят.
2. **Самодиагностика молчащего входа:** «молчание» (rms ≈ 0 непрерывно ≥ 5 с,
   состояние `muted` из решения #34) → в предупреждение добавлена конкретная
   инструкция: открыть `/audio-debug.html` (кнопки «Проверить микрофон (5 с)»,
   «Проверить с AEC (как в приложении)», «Тест AudioWorklet (4 с)», «Тест
   резервного пути (6 с)», «📤 Диагностика (9 с) — отчёт агенту»).
3. **UI-статусы переходов:** каждый переход цепочки (worklet → fallback →
   повторная инициализация; исчерпание лимита; `denied` при ошибке
   `getUserMedia`) сопровождается **info-сообщением** (`onInfo` в
   `MicCaptureEvents`) — не блокирующим, не «красной» ошибкой; только исчерпание
   лимита и `denied` — ошибки.

## Альтернативы
- **Ретраит по тишине (rms ≈ 0 → пересоздать захват):** отвергнуто — браузер
  **не позволяет отличить «мёртвый путь» (нули из мёртвого источника) от
  реальной тишины** (кандидат молча слушает/думает). Ретраиты — только по
  **отсутствию чанков** (мёртвый путь), не по уровню.
- **Никакой повторной инициализации (только worklet → fallback, как до 2026-10-08):**
  инцидент показал, что оба пути могут «умереть» одновременно (нулевой
  источник); без пересоздания `getUserMedia` пользователь завис в слепой сессии
  без подсказки.
- **Мгновенная ошибка при первом мёртвом пути (без fallback/ретраитов):**
  хуже UX — большинство сбоев (headless-окружение, зависший worklet) лечится
  одним переходом, кандидату не нужно ничего делать.
- **Автоматическая повторная инициализация без лимита:** бесконечный цикл
  пересозданий при системной причине (отключённый на ОС микрофон, снятое
  разрешение) — лимит попыток обязателен.

## Последствия
- + Мёртвый захват (оба пути) сам лечится пересозданием без участия кандидата;
  когда авто-цепочка бессильна — пользователь получает **конкретное действие**
  (открыть `/audio-debug.html` и прогнать проверки).
- + Переходы видны в UI (info-статусы) — «молчание сессии» перестаёт быть
  невидимым.
- + Поведение детерминированно тестируемо: цепочка — чистые переходы состояний
  (см. `docs/TEST_PLAN.md` §2.7, vitest `src/audio/mic.test.ts`).
- − Доп. пересоздания захвата (перерыв потока, дребезг UI) возможны, но
  **только в аномальном режиме** (чанки реально не приходят) и ограничены
  лимитом попыток; в штатном режиме пересозданий нет.
- − `getUserMedia` повторно запрашивает устройство — при снятом пользователем
  разрешении повторная инициализация сразу уйдёт в `denied` (обрабатывается
  как ошибка с диагностикой).
- Ограничение: различить «мёртвый путь» и «реальная тишина» браузер не может —
  **ретраит по тишине уровня НЕ делается** (решение #34 остаётся
  наблюдающим: `muted` → предупреждение + инструкция, а не пересоздание).
- Ограничение: пользователь **всегда может включить микрофон вручную**
  (toggle) — авто-цепочка не блокирует ручное управление.
- `/audio-debug.html` и dev-хуки (live-отчёт `/debug/mic-report`, `console.info
  mic-debug`, `debugInfo()`) **остаются dev-инструментами** (за флагами
  `ENABLE_DEBUG` / `VITE_MIC_DEBUG`) и не являются частью prod-контракта.
