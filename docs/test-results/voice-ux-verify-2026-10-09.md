# Voice UX — верификация и инцидент «стale-бинарник api» (2026-10-09)

## Инцидент (сообщён пользователем, воспроизведён и устранён)

Симптомы в живом браузере (22:00–22:15):
1. Надиктованная реплика отправлялась **сразу**, на каждой паузе ИИ отвечал
   на неполное сообщение («не диалог, а черт знает что»).
2. Ошибки в консоли/сессии: «неизвестное событие: recording» (и другие).

### Корневая причина (одна на оба симптома)

Бинарник `grade-api` в работе — от **2026-10-08 20:34**, а код режима записи
(FR-S8, `case "recording"` в `handleUIEvent`) закоммичен **2026-10-09 21:10**
(`08a6bff..bc0f26a`) — **api не был перезапущен** после pipeline-итерации.
Vite hot-reload обновил браузер (новый JS), сервер остался старый:
- клиент шлёт `{"type":"ui","name":"recording",...}` → в старом бинарнике нет
  такого case → `unknown_ui_event: неизвестное событие: recording`;
- PCM при этом шёл по старому авто-пайплайну (VAD-пауза ≥900 мс → turn на
  неполной реплике) — симптом 1.

Подтверждено: `pcm-debug`-стрим сессии 14 на старом бинарнике; `git log` vs
mtime бинарника; после пересборки+рестарта оба симптома исчезли.

### Почему бинарник остался старый: механизм «тихой» сборки

`go build -o <существующий файл>` при неизменённом коде (линк-кэш) **не
переписывает файл** (проверено: mtime не меняется, exit 0). Если ранняя
сборка итерации прошла с ошибкой/на старом коде, `run-all.sh build`
«успешно» не обновлял бинарник. Фикс: `scripts/run-all.sh do_build` — сборка во
временный файл + атомарный `mv` + проверка mtime (громкий сбой при
не-обновлении).

## Устранение и доработки (по запросу пользователя)

- Пересборка+рестарт api со свежим кодом (22:19).
- UI (тот же коммит-цикл):
  - кнопка мика при включённом мике — **«Отправить»** (было «Выключить
    микрофон»); нажатие = отправка буфера + выключение мика;
  - пока ИИ отвечает (`speaking`, мик выключен) — **«Ожидание ИИ…»**
    (disabled, не перебиваем ИИ);
  - окно записи: вместо «Отправить сейчас» — **«Очистить буфер»** (сброс
    накопленного, запись продолжается — ответ можно надиктовать заново;
    disabled при пустом буфере).
- Регресс-тест: `TestRecordingUIEventsNoUnknown` (api) — сервер обязан понять
  `recording`/`utterance` без `unknown_ui_event` (эта класс ошибки больше не
  пройдёт незаметно).
