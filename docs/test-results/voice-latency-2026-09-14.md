# Голосовой контур: latency и качество STT — 2026-09-14

**Задача Фазы 4** (TEST_PLAN §3). Живой контур: api (LLM_MOCK, VAD 900 мс) →
voice (faster-whisper CPU + Silero v5) → WS. Методика: `services/voice/latency/probe.py`
(WS-клиент: фразы эталона синтезируются Silero TTS (24 кГц), ресемплингуется в
16 кГц (контракт WS, ADR-001), шлётся чанками 250 мс с непрерывным «микрофоном»
(речь + 12 кадров тишины — VAD ждёт EndSilenceMS в потоке); до отправки — ожидание
конца TTS-приветствия по flag 0x0001 — turn-taking).

**Эталон:** 20 фраз (dev-речь кандидата, 2–3.3 с), `services/voice/latency/etalon20.json`.
Синтетическая речь (Silero eugene) — верхняя граница качества; живая речь будет хуже.

## Замеры (CPU, 20 прогонов/модель)

| Метрика | tiny (int8) | small (int8) | Цель (TEST_PLAN) |
|---|---|---|---|
| stt p50 / p95 (от начала отправки) | 5.76 / 6.52 с | 5.76 / 6.52 с | p95 < ~2.5 с до STT-результата* |
| tts-старт p50 / p95 | 5.76 / 6.53 с | 5.76 / 6.52 с | p95 < ~4 с (с LLM-моком) |
| Качество STT (среднее сходство, Левенштейн) | 0.68 | **0.87** | ≥ 0.85 |

*Разбивка p50 (фраза ~2 с): конец реплики VAD ≈ 2 + 0.9 = 2.9 с + распознавание
whisper int8 CPU ≈ 2.3–3.2 с (зависит от длины реплики, p95 — на фразе 3.3 с).
LLM-ответ (мок) — мгновенно; TTS-старт (Silero, CPU, короткая реплика) — +<0.1 с.

## Выводы

1. **Конвейер работает сквозным**: 20/20 фраз — VAD → STT → LLM → TTS, без потерь
   ходов, turn-taking соблюдается (пробер ждёт конца приветствия).
2. **Качество STT**: tiny — 0.68 (ниже порога 0.85), small — 0.87 (порог пройден
   в 18/20, провалы 0.62–0.73 — фразы с терминологией: Prometheus/Kafka/JWT,
   «код-ревью», «облако»). Рекомендация для prod: **small на CPU** (MVP) и
   **large-v3 на GPU** (SRS) — ожидается рост качества на 0.9+; дефолт
   `.env.example` (STT_MODEL=small) подтверждён.
3. **Latency**: доминирует распознавание (non-streaming whisper, int8 CPU).
   До SLO «p95 mic→TTS < 4 с» не дотягиваем (~6.5 с p95) — декомпозиция:
   STT non-streaming ~2.3–3.2 с + VAD-хвост 0.9 с + LLM (в проде 1–3 с на
   Qwen3.8-27B). Пути к SLO (бэклог, ADR-002/003-обновление): стриминговый STT
   (faster-whisper chunked / whisper-streaming), уменьшение EndSilenceMS до 700 мс
   (компромисс с паузами в речи), GPU.
4. ТТS (Silero v5 CPU) — не узкое место для коротких реплик (<0.5 с синтеза).

## Ограничения

- Синтетическая речь, один спикер; живая речь (шум, темп) — ниже качество.
- LLM-мок — реальный Qwen3.8-27B добавит 1–3 с к latency ответа (не к старту TTS
  первой реплики — она уже учтена в SLO-цели).
- CPU-замер (нет GPU-узла в окне Фазы 4, TEST_PLAN §7.1) — GPU-конфигурация
  остаётся бэклогом (large-v3 + стриминг).
- Побочные находки: (a) `LOG_LEVEL` читается из окружения, но не применяется к
  логгеру (debug-логи не пишутся) — баг, бэклог; (b) TTS-кадры api шлёт burst'ом
  (без real-time pacing) — на фронте воспроизведение корректное, для стриминга
  TTS (бэклог) потребует pacing.
