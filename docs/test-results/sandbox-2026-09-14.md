## Найденный и исправленный баг (критичный)

**Мёртвый цикл таймаута subprocess-режима** (до исправления — тест зависал
на 5+ минут): `exec.CommandContext` убивает только родительский `sh`, а
дочерние процессы (python/go) продолжают удерживать пайпы stdout/stderr —
`cmd.Wait()` ждёт EOF по пайпам **вечно**, и `syscall.Kill(-pid)` (вся группа)
выполнялся только **после** возврата Wait — недостижимый код.

**Исправление** (`runner.go, runSubprocess`): `exec.Command` + конкурентный
`select { case <-waitDone: case <-ctx.Done(): Kill(-pid, SIGKILL); <-waitDone }`
— группа убивается **до** завершения Wait, пайпы закрываются, Wait завершается.
Проверено: TestSandboxProbeInfiniteLoop 1.50 с (ранее — зависание).
