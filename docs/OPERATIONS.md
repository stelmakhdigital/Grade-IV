# Эксплуатация

Для тех, кто поднимает и держит боевой стенд. Разработка — [DEV.md](DEV.md),
устройство системы — [ARCHITECTURE.md](ARCHITECTURE.md).

## Развертывание

Один compose-файл, прод в профиле `prod`. Из рабочей копии репозитория:

```bash
cp .env.example .env                     # заполнить: JWT_SECRET, POSTGRES_PASSWORD
bash scripts/download-models.sh          # модели STT/TTS (~600 МБ)
docker compose -f infra/docker-compose.yml --env-file .env --profile prod up -d --build
```

`make up` делает то же с `--build` на переднем плане; `make down` — остановить.

Проверить, что встало:

```bash
curl -fsS localhost/api/v1/health                    # voice: провайдеры и loaded
docker compose -f infra/docker-compose.yml ps        # все healthy
```

Первый зарегистрированный пользователь становится админом (`internal/db/db.go:253`).
Регистрируйте администратора до того, как страница откроется наружу.

## Обязательные условия прод-профиля

- `JWT_SECRET` обязателен (`${JWT_SECRET:?}`); шаблонные значения api отвергает на
  старте (`internal/config/config_test.go:13-41`).
- `LLM_MOCK=1` в прод-профиле запрещён — api не стартует (ADR-005).
- `GRADE_UID`/`GRADE_GID` — uid/gid, под которым контейнеры пишут в бинды. Если
  каталоги уже созданы root'ом от предыдущего запуска, их надо переканить, иначе
  sandbox и voice падают на записи.
- Модели должны быть скачаны заранее. Без `models/stt-gigaam/v3_e2e_rnnt.ckpt`
  STT молчит (контракт — пустой текст, не 500), `GET /api/v1/health` показывает
  `stt.provider=gigaam, loaded=false`, в логе voice — ERROR с точным путём.
  Автоскачивание в рантайме мертво: у Sber-CDN сертификат просрочен, urllib внутри
  `gigaam.load_model` отказывается качать (см. `AGENTS.md`).

## Входы наружу

Наружу публикуются только входы caddy:

- `:80`/`:443` — TLS. `GRADE_DOMAIN` + `CADDY_TLS` (по умолчанию домен `localhost` и
  внутренний CA caddy: браузер ругается на сертификат, пока корневой сертификат не
  добавлен в доверие).
- `:16870` — `http://` без TLS, для доступа по адресу машины в локальной сети.
  Нужен потому, что на адресе `https://<ip>` с внутренним CA не работает, а
  микрофон в незащищённом контексте браузер не даёт. Следствия: трафик в сети
  открытый, голос на этом входе недоступен (кнопка микрофона честно объясняет
  причину), вход убирается удалением второго site-блока в `infra/caddy/Caddyfile`
  и проброса порта в compose.

Мониторинг (профиль `monitoring`) публикуется только на loopback: Prometheus
`127.0.0.1:9090`, Grafana `127.0.0.1:3000`.

## Песочница

Docker-путь идёт через socket-proxy с allowlist
(`tecnativa/docker-socket-proxy:v0.5.0`, `infra/docker-compose.yml`), сокет докера
в песочницу не монтируется: контейнер-исполнение может создать контейнер, список и
удалить свой, но не видит хост и чужие контейнеры. Лимиты — ADR-003.

Общий GOCACHE в named volume `grade_gocache`. Это не косметика: без общего кэша
первая сборка Go под лимитами стоит 40+ секунд, с кэшем ~1,4 с.

## Обновление и схема

Миграции накатываются api на старте (`internal/db/db.go:108`), 41 переход,
идемпотентно, откатов нет — схему меняют вперёд-совместимо. Перед `up --build`
 имеет смысл сделать дамп:

```bash
docker compose -f infra/docker-compose.yml exec -T postgres \
  pg_dump -U grade grade > backup-$(date +%F).sql
```

## Мониторинг и метрики

`/metrics` у api под basic-auth: `infra/monitoring/prometheus.yml` содержит
плейсхолдеры `@METRICS_USER@`/`@METRICS_PASSWORD@`, compose подставляет значения из
`.env` через sed на старте (пароли в git не попадают). Настройки Prometheus —
`infra/monitoring/prometheus.yml`, профиль `monitoring`.

## Частые симптомы

| Симптом | Причина и что делать |
|---|---|
| Микрофон «нет доступа» на адресе машины | не защищённый контекст: открыть `http://localhost:…` на самой машине или поднять TLS с доверенным сертификатом |
| Интервьюер молчит, health `loaded=false` | модель STT не скачана: `bash scripts/download-models.sh`, перезапустить voice |
| `429` на входе | сработал лимит частоты (`internal/httpapi/ratelimit.go`); `Retry-After` в ответе, лимиты по аккаунту независимы от лимитов по IP |
| Go-решение собирается десятки секунд | не примонтирован `grade_gocache` или сменился образ сборки |
| Контейнеры падают на записи в бинд | `GRADE_UID`/`GRADE_GID` не совпадают с владельцем каталогов |
| Отчёт «генерируется» и не кончается | LLM-узел недоступен: клиентский таймаут не убивает начатую генерацию, но без ответа отчёт не появится; смотреть лог api |
