# BUG-20261104-027: файлы градатора уходили кандидату в stage-сообщении

**Дата:** 2026-11-04
**Серьёзность:** P0 (утечка градатора)
**Статус:** closed (fix: sanitizeTasks в ws.go)

## Симптомы
Stage-сообщение livecode несло `tasks[].files` — полный набор файлов задачи из
банка sandbox, включая доверенные файлы градатора: `check.sh` (shell),
`*_test.go` (go), `test_*.py` (python). Кандидат видел их вкладками редактора,
мог открыть и ПРАВИТЬ (клиент отправляет все файлы редактора в /runs).

Для shell-задач check.sh — весь градатор: кандидат мог дописать в него `exit 0`.

## Причина
`liveCodeTask.Files` сервился как есть («полный набор файлов задачи, §4.4»).
Доверенность тестов при этом не страдала — sandbox подставляет файлы банка по
task_id на /runs — но санитизации на границе не было.

## Исправление
- `ws.go`: `sanitizeTasks(tasks, stack)` — убирает файлы градатора перед
  отправкой (`isGraderFile`: go `*_test.go`; python `test_*.py|*_test.py`;
  shell `check.sh`) — в stage-сообщении И в событии `livecode_tasks`
  (транскрипт хранится уже чистым).
- Комментарий в `liveCodeTask.Files` переписан: файлы кандидата — шаблон
  решения и статические данные; исполнение — только файлы банка.

## Проверка
WS-проба: stage-livecode несёт `tasks:[{files:["solution.sh"]}]` — check.sh
отсутствует; вкладки редактора: только solution.sh; «Запустить тесты»
по-прежнему прогоняет check.sh из банка (проверено E2E sysadmin middle).
