# BUG-20261122-030: AudioWorklet молчал ВСЕГДА — сессии всегда шли через резервный захват

**Дата:** 2026-11-22
**Серьёзность:** P1 (резервный ScriptProcessor тянул захват, поэтому микрофон
«работал»; но основной путь не работал никогда, и на каждом старте висело
предупреждение «включён резервный захват»)
**Статус:** closed (fix: процессор собран по контракту AudioWorklet)
**Связано с:** BUG-20261011-007 (там лечили `ctx.resume()` — симптом вернулся,
потому что корень был глубже)

## Симптомы
«Включить микрофон» → через ~3 с «Микрофон: основной путь (AudioWorklet) молчит,
включён резервный захват» — на каждой сессии, на каждой машине. Эквалайзер оживал
только после переключения на резерв.

## Причина
`WORKLET_CODE` (`services/frontend/src/audio/mic.ts`) нарушал две вещи контракта
AudioWorklet:

1. `class PcmCapture { ... }` — без `extends AudioWorkletProcessor`. `port` даёт
   базовый класс; Chrome не может собрать такой инстанс и валит процессор в
   `processorerror` — `process` не вызывается вообще.
2. Опции читались flat: `params.inputRate`, `params.chunkSamples`. В процессор
   приходит `{ numberOfInputs, numberOfOutputs, outputChannelCount,
   processorOptions }` — то есть `params.inputRate === undefined`,
   `chunkSamples === undefined`, и `while (accLen >= undefined)` не выполняется
   никогда: чанки не отправлялись бы даже с исправленным пунктом 1.

Тесты этого не видели: `mic.test.ts`/`mic-silence.test.ts` подменяют
`AudioWorkletNode` моком и тело процессора не исполняют.

## Исправление
`WORKLET_CODE`: `class PcmCapture extends AudioWorkletProcessor` + `super()`,
опции — из `options.processorOptions` с дефолтами (`sampleRate` — глобал
AudioWorkletGlobalScope, `TARGET_RATE`/250 мс — из констант модуля). Заодно
`process` возвращает `true`, а не `[true]` (по спецификации — boolean).
Регресс закрыт новым тестом `src/audio/worklet.test.ts`: процессор собирается с
заглушками глобалов AudioWorkletGlobalScope и кормится квантами по 128 отсчётов —
без базового класса или с flat-опциями чанков нет.

Проверено в Chromium (Playwright, источник сигнала — осциллятор вместо микрофона):
3 чанка в секунду по 4000 отсчётов 16 кГц (250 мс), rms чанка = уровень сигнала,
~9 сообщений уровня в секунду, `processorerror` нет.

## Косметика рядом (тот же фидбек)
- `useVoiceSession`: info-предупреждения (`onInfo`) гасятся сами через 8 с —
  раньше висели в `.form-error` до конца сессии. Настоящие `onError` не гасятся.
- `.session-head .head-actions` — кнопки одной ширины; в `.voice-controls` кнопка
  «Отправить» текстового ответа больше не `small` (ряд был разнокалиберный).
- Кабинет, «Новое интервью»: у кнопки резюме появилась подпись сверху (как у
  селектов), она же — той же ширины; статус резюме, ошибка и бриф вынесены
  своими строками, кнопка «Начать интервью» встала в ряд контролов.
