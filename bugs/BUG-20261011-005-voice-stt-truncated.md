# BUG-20261011-005 · V1: «Отправляется только часть распознанного текста»

- **Статус:** исправлено
- **Область:** `services/api/internal/httpapi/voice_pipeline.go` (стрим-путь STT)

## Симптом
Кандидат говорит долго (много фраз) — в чат/историю уходит только фрагмент; в истории
застревает запись «распознаётся ⋯» (частичный STT не финализируется).

## Шаги воспроизведения
1. Voice-стадия, активный TTS/ход. Кандидат отвечает длинно (много фраз, с паузами).
2. Стриминговый STT (voice `/stt/stream`, Silero VAD) режет длинную речь на несколько
   **final**-ов: по тише ≥ `VAD_MIN_SILENCE_MS=600 мс` (граница фразы) и/или принудительно
   по `VAD_MAX_SPEECH_S=30 c`. Каждый final — `{type:final, text, speech_ms}`.
3. Первый final → ход кандидата (`busy=true`, `runStreamTurn` → LLM). Далее идёт LLM-фаза
   (несколько секунд), `busy` остаётся занятым.
4. Следующие final-ы (фразы 2..N) приходят пока `busy`:
   `handleSTTStreamFinal` → нормальная ветка → `if !w.busy.CompareAndSwap(false,true) return`
   → **реплика отбрасывалась** («допустимо в ходовом режиме»).

## Корень
Голосовой конвейер **ходовой** (один параллельный ход, turn-taking, флаг `busy`). Long-
уттеранс режется VAD на несколько final-ов; первый запускает ход, а остальные приходят в
LLM-фазу (busy) и **терялись**. Итог: в LLM/чат уходит только первый сегмент (фрагмент
реплики), а `transcript(user)` для остальных сегментов не шлётся → клиентский partial
(«распознаётся ⋯») **не финализируется** и висит. Это не тайминг/VAD-порог и не усечение
в LLM — это семантика busy-отброса consecutive-final-ов.

## Фикс
Отбрасываемые final-ы **не теряем**: накапливаем (`appendSTTPending`, мьютекс-буфер на
сессии) и после завершения текущего хода (`flushSTTPending` в `defer` у `runStreamTurn`)
отправляем накопленное **следующим ходом** (conf высокий — текст уже распознан; если ИИ ещё
говорит — barge-in `stopTTS`). Идёт до тех пор, пока не закончится очередь. Интенсиональный
отброс коротких реплик во время TTS (анти-ложный barge-in, `ms < BargeInMinSpeechMS`) не
трогался.

Регресс: api `go test ./...` зелёный (voice_pipeline_test, vad_stream_test, barge-in);
тесты не менялись.
