# BUG-20261014-019: любые pause/resume/finish без проверки владения сессией

## Симптом
Любой аутентифицированный пользователь мог изменять состояние ЧУЖИХ сессий:
ставить в паузу, возобновлять, завершать (включая запуск генерации отчёта и
тарификации минут другого пользователя).

## Шаги воспроизведения
1. Пользователь A (qa-nonadmin-1@example.com) узнаёт id чужой сессии (перебор
   `POST /api/v1/sessions/{id}/finish`).
2. Сессия пользователя B завершается; минуты B списываются; B видит «сессия
   завершена» без своего участия.

## Причина
`handleSessionAction` вызывал `engine.Pause/Resume/Finish(id)` сразу после
`parseSessionID` — `GetOwned` выполнялся уже ПОСЛЕ действия и лишь для
построения DTO ответа (session_handlers.go).

## Исправление
- Проверка владения первой строкой: `ownedSession(w, r, id)` до switch
  (commit `834ca68`).
- Сопутствующее: после рестарта сервиса recovery ставил активные сессии в
  паузу только в БД — REST pause/resume/finish для них возвращал
  ErrNotAttached (409) навечно; движок теперь реконструирует runtime из БД.
