# BUG-20261011-002 · Live-Code: код кандидата и результат запуска терялись при перезаходе

- **Статус:** исправлено
- **Грейды:** все; **Область:** `services/frontend/src/views/livecode/LiveCodePanel.tsx`

## Симптом
Кандидат на стадии livecode пишет код, запускает тесты, уходит на design (или в
livecode снова) — при возврате **редактор очищается до шаблона задачи**, а результат
последнего запуска исчезает. Правки кандидата теряются.

## Шаги воспроизведения
1. Стадия livecode, ввести код, «Запустить тесты» (результат виден).
2. Перейти на design (кнопка «К System Design») и вернуться («К Live-Code (назад)»).
3. Панель LiveCodePanel **размонтировалась** при уходе (тернарное в SessionView рендерит
   только активную стадию) и **заново смонтировалась** с `taskFiles`/шаблоном → код
   кандидата = шаблон, `result` = null.

## Корень
Состояние кода/результата жило **внутри** LiveCodePanel (`useState`). Смена стадий
размонтирует компонент (в SessionView рендерится только активная панель), состояние
теряется, при повторном монтировании инициализируется из `taskFiles` (задача) — не из
правок кандидата. Бэкенд хранит сдачу (submissions), но UI её не подхватывал.

## Исправление
SPA-кэш кода + результата последнего запуска, **ключ = sessionId + стек + набор файлов
задачи** (key-set). Повторный вход в ту же задачу/стек → восстановление кода и результата;
другая задача/стек → своё ключевое пространство (чужой код не подставляется). Кэш живёт в
модуле, переживает размонтирование панели; taskFiles из WS не затирает восстановленный код.

## Ограничение (закреплено)
Кэш — в рамках SPA (вкладка). Полный перезапуск страницы (F5) кэш не переживает; последняя
**сдача** сохраняется сервером (submissions, попадает в отчёт). Восстановление последних
*несданных* правок после F5 потребовало бы бэкенд-хранилище решения сессии (GET) — вне
этой итерации.
