# BUG-20261121-029: на телефоне по http://IP микрофон «отказывался» с обещанием разрешить в браузере

**Дата:** 2026-11-21
**Серьёзность:** P2 (тупик для пользователя: подсказка ведёт в никуда)
**Статус:** closed (fix: честная причина — нужен HTTPS/localhost)

## Симптомы
Открытие интервью с телефона в браузере (адрес вида `http://192.168.x.x:5173`)
→ «Включить микрофон» → «Нет доступа к микрофону — разрешите в браузере».
Браузер запрос на разрешение микрофона не показывал, разрешать было нечего.

## Причина
`getUserMedia` доступен только в secure context: HTTPS, `localhost` или
`127.0.0.1`. По `http://<LAN-IP>` у браузера нет `navigator.mediaDevices`,
вызов падает с TypeError ещё до всякого разрешения. `catch` в
`useVoiceSession.toggleMic` не различал «отказали» и «API нет» — наружу
шла подсказка про настройку разрешений.

С desktop-машины не проявлялось: разработка идёт на `http://127.0.0.1:5173`
(vite биндится на loopback), TLS есть только в compose-профиле prod (Caddy).

## Исправление
`mic.ts`: `micUnsupportedReason()` — проверка наличия
`navigator.mediaDevices.getUserMedia`; `initCapture` с ней не доходит до
getUserMedia, а ставит state `denied` и сообщает причину: «браузер даёт доступ
к микрофону только по HTTPS (или localhost)». `useVoiceSession.toggleMic` в
catch подставляет ту же причину вместо общей фразы (при настоящем отказе
остаётся прежний текст).

## Проверка
vitest: `mic.test.ts` — без `navigator.mediaDevices` старт отклоняется,
`onError` содержит «HTTPS», состояние `denied`; со стабом — причины нет.
Вся фронт-сьюта 134 passed, tsc ok.
