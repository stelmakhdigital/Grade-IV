# BUG-20261014-020: обрыв WS — микрофон молча «говорит в пустоту», reconnect нет

## Симптом
При обрыве WebSocket (сетевой сбой, сон ноутбука, рестарт api) клиент:
- не переподключался — `wsState='closed'` навсегда, кнопки мертвы;
- MicCapture продолжал работать: `sendPcm` возвращал false без диагностики,
  визуализатор «дышал» от локального RMS — кандидат уверен, что его слышат;
- диктовка в режиме записи (recording on) при закрытом WS молча терялась:
  `finishRecording` не проверял результат `sendUi` (off/utterance).

## Причина
1. В хуке useVoiceSession не было reconnect-логики; onClose ставил 'closed'.
2. `ws.ts`: сервер шлёт код закрытия 1002 (StatusProtocolError при
   session_ended/not_found) — клиент ждал только 1011, ветка «Сессия
   прервана» не срабатывала по WS; onerror+onclose давали двойной onClose.
3. `finishRecording`: `wsRef.current?.sendUi(...)` — результат игнорировался.

## Исправление
- Авто-reconnect с backoff (5 попыток, 1→16 с), состояние `reconnecting`;
  при переподключении — авторезум по REST (сервер спаузил сессию при
  engine.Detach) + ре-синк recording (BUG-20261012-018 в onOpen).
- ws.ts: single-shot close; 1002/1011 → 'aborted'; кнопка
  «Переподключиться» и честный текст статуса соединения.
- `sendBufferedRecording`: проверки sendUi; при сбое буфер сохраняется,
  повторная отправка — кнопкой «Отправить» после восстановления.
- Отчёт для прерванной по pause_timeout сессии теперь генерируется (раньше
  ReportView поллил «Считаем результаты…» вечно) — BUG-20261014-021.

Коммиты: `0c2a5fa`, `f050b66`.
